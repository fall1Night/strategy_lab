## 修复：多策略并发提交被误判「全部提交失败：undefined undefined」
- 现象：用户选多策略点回测，后台确实在跑（批次已创建并运行），但前端弹「全部提交失败：undefined undefined；undefined undefined」。
- 根因（前端 bug，web.py `runBacktest` 的 `Promise.allSettled` 回调）：`Promise.allSettled` 返回元素结构是 `{status, value, reason}`，真实结果对象 `{ok,d,strategy,error}` 在 `r.value` 内；原代码直接读 `r.ok`/`r.d`（在 `{status,value}` 上恒为 undefined）→ 所有提交被判 failed；失败项 `f.strategy`/`f.error` 也是 undefined → 文本显示 undefined。后端 `_api_submit_batch` 实际早成功执行（所以后台在跑），只是前端解析错、没接管进度。
- 修复：回调里先 `settled = results.map(r => r.status==='fulfilled' ? r.value : {ok:false,strategy:'(请求异常)',error:String(r.reason)})`，再 `settled.filter(r=>r.ok)`。同时让真实后端错误（d.error）也能正确显示策略名+原因，不再 undefined。
- 验证：`py_compile` 通过；提取全部 5 个 `<script>` 块 node --check，production 页块（含 runBacktest）JS_OK。
- 提醒用户：本次修复前那次误点击其实已在后台创建了批次（前端没接住）；修复后点一次会重新创建批次，旧批次可通过「批次监控」或 cancel 清理。

## 增强：多策略进度卡「时间维度」可见性
- 现象：修复「全部提交失败」后，用户反馈多策略回测「没有时间进度条」。
- 诊断：进度卡 HTML 与聚合逻辑（`prog-bar` 百分比条 + `prog-eta` 预计剩余）其实都在、且单/多策略共用同一卡片；后端 `get_progress` 的 `eta_seconds` 仅在 `done_count>0` 时计算，否则为 None。多策略大范围回测时 `done_count` 还没到 1 的阶段，前端把 null 渲染成「—」，且进度条 pct 因 total 巨大增长慢，主观像「没进度/没时间」。
- 增强（纯前端，src/strategylab/web.py · build_production_html）：新增全局 `batchStartTs`；进度卡加「已运行：<b id="prog-elapsed">」；`beginMulti` 记录 `batchStartTs=Date.now()`；`renderBatchAgg` 中①持续显示已运行=`fmtEta((now-batchStartTs)/1000)`；②ETA 三态——无 running「—」、有 eta 显示预计剩余、有 running 但都 done=0 显示「计算中…」（替代原「—」）。单策略 `beginBatch`→`beginMulti` 同样受益；旧单批次 `poll()` 已不存在，无遗漏路径。
- 验证：`py_compile` 通过；全部 `<script>` 块 node --check（block1 的 `{{}}` 占位符误报属既有、无关）；`prog-elapsed/batchStartTs/计算中…/已运行` 均确认在源码内。需重启 web 服务 + 浏览器硬刷新生效。
