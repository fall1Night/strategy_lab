## 最大回撤口径改为「历史交易记录里的最大单笔回撤占比」
- 需求：回撤数据里的 `最大回撤` 改成显示「历史交易记录里占比最大的回撤」，而非「总历史回撤」（整条权益曲线跨交易的峰值→谷值）。
- 口径：逐笔交易截取 `[entry_date, exit_date]` 区间的账户权益曲线，计算该笔持仓内的峰值→谷值回撤（账户权益相对滚动峰值的跌幅 %，与整条曲线回撤同源），再取所有交易中的最大值作为 `max_drawdown_pct`；某笔区间缺日期/不足 2 点则跳过；无任何有效交易时回退到整条权益曲线最大回撤。
- 实现（两处 `_compute_window_summary` 同步，避免跨交易口径漂移）：
  - `engine/vendor/export_results.py`：新增 `_max_trade_drawdown_pct(equity_curve, trade_history)`，原 `_compute_window_summary` 的整条曲线 `drawdown_curve` 计算改为调用它。该路径产出**落库 Summary**，是 rank_runs / 分析页表 / 统计面板 / dashboard KPI 的唯一数据来源。
  - `engine/vendor/render_dashboard.py`：同款 `_max_trade_drawdown_pct`（未用相对导入，避免破坏 CLI `python render_dashboard.py` 调用），其 `_compute_window_summary` 同步改用。render_dashboard 仅在落库 summary 缺字段时回退用此值，故两处一致即可。
- 消费者自动同步：`web.py` 分析页「最大回撤」列、统计面板「最大回撤分布」、dashboard KPI 均直接读 `max_drawdown_pct`，无需改 web.py。
- 验证：`py_compile` 两文件通过；合成用例（trade1 区间峰1200谷1150≈4.17%、trade2 峰1150谷1000≈13.04%，整条曲线峰1200跨交易谷1000≈16.67%）确认逐笔取最大=13.04%、整条=16.67%、无交易回退=16.67%、全涨单笔=0.0；export_results 与 render_dashboard 两副本结果一致。
- ⚠️ 仅影响**新回测**：已落库的历史 run 仍存旧（整条曲线）口径，需重跑才刷新。需重启 web 服务生效。
- 注：账户权益含现金缓冲，故逐笔回撤是「账户层面持仓区间回撤」（= 仓位回撤 × 持仓占比），非纯价格 MAE；若用户要纯价格最大不利变动需另接 price_curve。
