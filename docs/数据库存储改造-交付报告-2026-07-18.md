## 3. 数据库 Schema（5 张表）

| 表 | 作用 | 关键字段 |
|----|------|---------|
| `backtest_runs` | 每次回测元信息（1 行/run） | `run_id`(PK,String36) / `batch_id`(同批共享) / `strategy_type` / `symbol` / `start` / `end` / `initial_cash` / `params_json` / `positions_json` / `created_at`(UTC) |
| `equity_points` | 权益曲线逐点 | `run_id`(FK) / `date` / `value`(Numeric18,4) |
| `trades` | 逐笔交易 | `run_id`(FK) / `entry_date` / `exit_date` / `side` / `role` / `size` / `entry_price` / `exit_price` / `pnl` / `pnl_pct` / `holding_bars` |
| `summary` | 绩效汇总 | `run_id`(PK,FK) / `total_return_pct` / `annual_return_pct` / `max_drawdown_pct` / `sharpe`(Float) / `win_rate_pct` / `total_trades` |
| `schema_version` | 轻量版本表 | `version` / `applied_at`（`init_db` 自动补登 v1） |

关系：`BacktestRun` 1—* `EquityPoint` / `Trade`，1—1 `Summary`，删除 run 时 cascade 删除关联数据。

> **你不需要手动建表**：首次跑回测 / 起 Web 时，SQLAlchemy 的 `create_all`（`init_db()`）自动建好这 5 张表。你只需确保「空数据库」存在（见 §5）。

## 5. 使用方法

### 5.1 配置数据库连接（只需做这一次）
代码只用环境变量 `DATABASE_URL`，不硬编码。推荐写进 `.env`（已加入 `.gitignore`，不会进版本库）：

```bash
# MySQL（当前验证通过的配置）
DATABASE_URL=mysql+pymysql://root:root@localhost:3306/strategylab

# 或本地 SQLite（零依赖，开箱即用）
# DATABASE_URL=sqlite:///./strategy_lab.db

# 或 PostgreSQL
# DATABASE_URL=postgresql+psycopg2://user:pass@host:5432/strategylab
```

> 唯一需手动的：确保「空数据库」已存在。SQLAlchemy 能建表，**不能建库本身**。MySQL 下执行一次：
> ```sql
> CREATE DATABASE strategylab CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
> ```
> 之后表全部由代码自动创建，零建表脚本。

### 5.2 跑回测（结果落库）
```bash
python run.py --symbols 600216.sh 002001.sz --start 2023-01-01 --end 2024-12-31
# 多标的同批共享 batch_id；只落库，不再写三件套文件
python run.py --list-runs        # 查看已落库的所有回测
```

### 5.3 跨回测对比（Web）
```bash
python web_app.py                # 默认 http://127.0.0.1:8000
```
浏览器打开：
- `http://127.0.0.1:8000/history` —— 历史回测列表，多选 run → 一键「对比」
- 不同初始资金的回测，权益曲线会**自动归一化到 100** 再叠加，指标表保留各自原始 %

### 5.4 编程调用（对比 / 读取）
```python
from engine.storage import repository as repo
from engine.dashboard import build_compare_from_runs

runs = repo.list_runs(symbol="600216.SH", limit=10)
ids = [r["run_id"] for r in runs]
html = build_compare_from_runs(ids, out_path="compare.html")   # 返回 HTML 路径
```

## 7. 代码优化规范（本轮评审结论）

从专业 SWE 角度，本轮已落实的规范项：

1. **该落库的落库，文件不双写**：回测结果统一进 DB，删除历史三件套输出，并把 `export_results` 默认改为 `write_files=False`，从根上锁死"只落库不双写"。
2. **删除死代码**：移除 `backtest.py` 中无调用方、却引用 `trades.csv` 的 `_patch_trades_csv` 及其 `import csv`，消除误导性历史残留。
3. **生成物与源码分离**：`.gitignore` 明确排除运行产物（三件套 / 视图 HTML / `*.db` / 行情缓存 / `.env`），避免把运行数据误提交进仓库。
4. **DB 无关 + 单一来源**：连接串走环境变量，类型约定全部用跨库安全的 `String/Numeric/Date/DateTime`，`migrate.init_db` 委托 `db.init_db` 避免重复逻辑。

### 建议后续（非阻断，按需）
- `engine/vendor/render_dashboard.py` 仍是早期"文件版"渲染独立工具（示例路径写死 `ma_cross_600519_*`），与当前 DB 流程无关，可作为遗留工具清理或改造为读 DB。
- 行情 `*_daily.csv` / `*_weekly.csv` 目前散落在仓库根目录；后续可统一收进 `data/cache/` 并由 `data_feed` 读取，进一步与源码目录解耦（当前已 gitignore，不影响运行）。
