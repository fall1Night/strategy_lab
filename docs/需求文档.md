## 1. 背景与目标

### 1.1 背景
用户已验证一条量化策略（周线 MACD + 日线 KDJ 双入口建仓 + 日线 J 线做 T + 日线 MACD 水上死叉清仓），并希望把它从「一次性脚本」沉淀为**可长期复用、可维护、可服务化**的工具：能随时换标的、换区间、换策略跑回测，并产出可读的仪表盘。

### 1.2 目标
- **可复用**：策略参数全部配置化，改参数不碰代码。
- **可服务化**：提供零依赖网页服务，浏览器里选标的/日期/策略即可出图。
- **可追溯**：每次回测结果统一落库（数据库，DB 无关），可复核、可跨回测对比。
- **可扩展**：新增策略 = 加一个类（设 `type`）+ 写一份 `.toml`，由 `discover_strategies()` 自动发现注册，**零中心文件改动**，不影响现有代码。

### 1.3 非目标（明确不做）
- 不提供选股/截面因子研究（非本工具职责）。
- 不做盘中（分钟/tick）回测。
- 不接入真实券商交易，纯研究用途。
- 不提供期权/可转债等复杂衍生品定价。

## 2. 用户画像与场景

| 角色 | 特征 | 典型场景 |
|---|---|---|
| 个人量化爱好者（主用户） | 懂 K 线/MACD/KDJ 但编程有限 | 想把自己琢磨的策略快速跑历史回测看效果 |
| 策略维护者 | 同一个人，进阶后能改参数/加策略 | 调 J 阈值、底仓金额，对比不同参数下的收益 |

**核心用户故事**
- 作为用户，我希望**输入「浙江」就能搜到浙江医药**并点选填入，而不用手抄代码。
- 作为用户，我希望**改几个数字（底仓金额/阈值）就能重跑**，不必改 Python。
- 作为用户，我希望**一次对比多个标的**的策略表现，而不是逐个看。
- 作为用户，我希望**结果是一个能直接打开的网页**，含权益曲线、回撤、每笔成交和策略说明。

## 3. 功能需求

### FR-01 命令行回测
- `strategylab`（命令）/ `python -m strategylab` 接受 `--symbols`（1 个或多个）、`--start`、`--end`、`--strategy`、`--names`、`--out`、`--list-strategies`、`--list-runs`。
- 单标的与多标的**统一输出「策略对比」排版**仪表盘视图（`data/index.html`，仅渲染视图，数据已落库）。
- 每个标的的回测结果（权益曲线 / 成交 / 指标 / 持仓）**统一写入数据库**，不再产出 CSV/JSON 结果文件。
- 行情不足时自动联网取数并缓存到 `data/`，重复运行直接复用。

**验收**：给定 `002001.SZ` 与区间，结果落库（可用 `strategylab --list-runs` 查到）+ 生成可打开的 `data/index.html`；控制台打印各标的汇总指标与 `run_id`。

### FR-02 网页回测服务
- 零依赖（`http.server`），默认端口 8000，支持 `PORT` 环境变量覆盖。
- 表单页提供：标的多选输入、起止日期、策略下拉（读包内置策略 + `STRATEGALAB_STRATEGIES_DIR` 目录）。
- 提交后渲染与命令行一致的对比排版仪表盘，并提供「← 新建回测」返回入口。

**验收**：浏览器打开 `http://127.0.0.1:8000`，填表提交后返回完整仪表盘；点返回可重填。

### FR-03 标的联网实时搜索
- 标的是输入框（非静态下拉），输入即触发 `GET /api/search?q=关键词`。
- 后端从东方财富全 A 股列表接口取数（带 10 分钟缓存），按**名称或代码包含**关键词过滤，返回 `{code, name, symbol}`。
- 前端 200ms 防抖，弹出候选浮层，点击填入；支持逗号/空格分隔多个标的。
- 关键词为空/无命中时浮层隐藏，不报错。

**验收**：输入「浙江」→ 返回含「浙江医药」等候选；输入「600216」→ 精确命中 600216.SH。

### FR-04 策略库与配置化
- 每条策略 = 一个 `.toml`（内置在 `src/strategylab/resources/strategies/`，或放 `STRATEGALAB_STRATEGIES_DIR` 用户目录）。
- 配置含 `name` / `type` / `market` / `description` / `[params]`（含全部策略参数与风控开关）。
- 改参数重跑即生效，无需改代码。
- `--list-strategies` 列出已注册策略类型。

**验收**：复制 `.toml` 改 `base_buy_amount` 后重跑，结果中的建仓金额随之变化。

### FR-05 回测引擎（双入口建仓 + 做T + 清仓）
- **建仓**：周线 MACD 柱(hist)<0 进入监控区，两条平行入口：
  - 路径A：周 hist 较上周上涨 armed → 日线 J<50 尾盘买入底仓；hist≥0 解除监控。
  - 路径B：周 hist<0 且 周 J<30 且 周 J 上升 → 直接尾盘买入（不卡日线 J）。
- **单底仓约束**：同一时间仅持一笔底仓。
- **做T**：日线 J 较近 5 日高点回落 ≥30 且下降 → 买做T额；J>80 → 卖光全部加仓部分；底仓不动。
- **清仓**：日线 MACD 水上死叉（DIF>0、DEA>0、DIF 下穿 DEA）→ 当日收盘清仓全部。
- 期末强制平仓（`is_flat_at_end=True`），保证组合为空仓。

**验收**：成交记录中不存在「底仓未清又开新底仓」的重叠区间（见防御断言）；T 加仓发生在底仓窗口内。

### FR-06 结果可视化仪表盘
- 图表：权益曲线（含回撤带）、买卖点标记。
- 指标卡：总收益、最大回撤、交易笔数、胜率、夏普。
- 文本模块：策略实现要点、已知局限、免责声明。
- 对比布局：Tab1「策略对比」含多权益曲线 + 指标对比表；各标的中独立 Tab。
- 语言锁定为中文（`language="zh"`）。

### FR-07 结果落库（数据库，DB 无关）
- 回测结果（权益曲线逐日点、每笔成交、汇总指标、合并持仓）统一写入数据库（SQLAlchemy 2.0，DB 无关），由 `DATABASE_URL` 控制（默认 SQLite 本地文件，可选 MySQL/PostgreSQL）。
- **不再写出** `*_equity.csv` / `*_trades.csv` / `*_summary.json` 等结果文件。
- 提供 `strategylab --list-runs` 与网页 `/history` 查看历史，支持多选**跨回测对比**（权益曲线各 run 起点归一化到 100 再叠加；指标表保留原始 %）。
- 数据库存有 `backtest_runs`（元信息）、`equity_points`（逐日权益）、`trades`（每笔成交）、`summary`（汇总指标）、`schema_version`（版本）五张表。

### FR-08 合并持仓成交明细
- 一个持仓组 = 一笔底仓 + 其若干做T，下方缩进子行列出每笔做T收益。
- 自洽校验：`base_pnl + Σ做T pnl == total_pnl`。
- 详情仪表盘的持仓明细表 / 交易明细表，向下滚动时**表头固定显示在表格顶部**（sticky header，纯 CSS，需重启服务重渲后生效）。

### FR-09 按板块选股
- 网页表单提供「**按板块选股**」下拉，列出 **31 个申万一级行业**（半导体 / 白酒 / 化学制药 等）。
- 选定行业后弹出**成分股勾选面板**，用户勾选成分股（**单次最多 10 只**），可一键「全清」。
- 成分股数据来自 `data/sector_stocks.json`（约 5527 只，构建期一次性拉取缓存）；后端 `GET /api/sector-stocks?code=<行业code>` 读取返回。
- 勾选的板块标的与搜索框标的合并进入回测。

**验收**：选「化学制药」→ 面板列出该行业成分股 → 勾选 3 只 → 回测包含这 3 只。

### FR-10 界面统一显示股票名称（而非代码）
- 所有用户可见位置（搜索候选、已选标的、左侧历史、对比页标签、持仓明细）一律显示**股票名称**（如「浙江医药」），代码仅在后台对应。
- 提交时前端将「显示名」与「后台代码」分离（`real-names` / `real-symbols`），防止中文名被误当代码造成后端错误。

**验收**：界面任何位置不出现裸股票代码（如 600216.SH），均显示名称。

### FR-11 持仓明细增列（做 T 收益率对比）
- 合并持仓明细在原有列基础上，新增 **「持仓不动收益率」**（`hold_no_t_pct`，建仓持有到清仓、不含做 T 的回报）与 **「T持有到清仓收益率」**（`t_hold_to_exit_pct`，含做 T 的全部回报）。
- 两列之差直观体现做 T 对单笔持仓的增厚 / 拖累。

**验收**：持仓明细表含这两列，且「T持有到清仓收益率」≈「总收益率」。

## 3.1 v2.0 功能需求（批量扫描 + 数据仓库化）

> v2.0 核心理念：**两页解耦（数据生产 vs 数据分析）+ 一次跑多次查**。
> 回测区间固定为 `2020-01-01 ~ 今天`（前端去掉日期选择器）；命中复用条件 = `strategy_name + symbol + params_hash` 一致。
> 铁律：不引入 Redis/Celery 等重型中间件，仅用 Python 标准库 + MySQL。

### P0 — 核心闭环

#### FR-12 数据库迁移 v1→v2
- 新增 `batches` 表（批次元信息：strategy/params_hash/scope/total/done/failed/status/时间戳）。
- 新增 `batch_items` 表（批次内每只标的状态：symbol/sector_code/status/run_id/is_reused/error，`(batch_id,symbol)` 联合唯一）。
- `backtest_runs` 新增 `params_hash` 字段+索引，老数据回填。
- `init_db()` 启动时检测 schema 版本，v1 自动迁移到 v2（幂等）。
**验收**：启动服务后 MySQL 中出现 `batches`/`batch_items` 两表；`backtest_runs.params_hash` 已建索引且老数据已回填；`schema_version=2`。

#### FR-13 params_hash 计算与写入
- 对策略 `params`（规范化后）做 `sha1` 得 `params_hash`（40 字符）。
- `run_symbol` 落库时写入 `params_hash`；调参后 hash 变化，视为新 run。
**验收**：同参数重跑 `params_hash` 一致；改 `base_buy_amount` 后 `params_hash` 不同。

#### FR-14 命中复用预查
- 提交批次时一次性查询：`strategy_name + symbol + params_hash` 命中已有 run → 标 `skipped`+关联 `run_id`；未命中 → `pending` 入队执行。
- 命中取「最新一条」（`MAX(created_at)`）。
**验收**：第二次提交同策略同标的同参数的批次，全部 `skipped`，秒级返回。

#### FR-15 bulk_insert_mappings 优化
- `save_run` 改用 `s.bulk_insert_mappings(EquityPoint, [...])` / `s.bulk_insert_mappings(Trade, [...])` 批量写入，替代逐条 ORM append。
**验收**：单只回测落库耗时下降 10 倍以上；当前预热宇宙 1301 只全量明细写入可在合理时间内完成。

#### FR-16 批量扫描后台执行器
- 新增 `engine/batch_runner.py`：`ThreadPoolExecutor(max_workers=8)` 后台并发执行；内存 `threading.Event` 取消标志；单只失败 `try/except` 记录 `error_msg` 不终止整批；原子 SQL 更新 `batches` 计数。
- 区间固定 `start=2020-01-01, end=today`。
**验收**：提交 10 只标的的批次，后台 8 路并发跑完，`batches.status=done`，`batch_items` 状态正确。

#### FR-17 批次 API 端点
- `POST /api/batch`：提交批量扫描（板块/池/全市场预热），同步返回 `{batch_id, total_count, hit_count}`，后台异步跑。
- `GET /api/batch/<id>/progress`：返回 `{total, done, failed, skipped, running, status, current_symbol, eta}`。
- `POST /api/batch/<id>/cancel`：设置取消标志。
- `GET /api/batch`：批次历史列表。
**验收**：提交→轮询进度→取消 全链路可用；进度数据准确。

#### FR-18 数据生产页前端
- 新增 `/production` 页：表单（策略下拉 + 范围选择：板块多选/自定义池/全市场预热，**无日期选择器**）。
- 提交后 `fetch('/api/batch')` 拿 `batch_id`，2s 轮询进度，显示进度条+统计（已完成/总数/失败/跳过/ETA/当前标的）。
- 状态 `done/cancelled/interrupted` 时停止轮询，引导去分析页。
- 取消按钮。
**验收**：选板块→提交→看进度→完成，全流程顺畅。

#### FR-19 缓存 bug 修复（meta.json 区间校验 + 原子写）
- `data_feed.py` 新增 `<prefix>_meta.json` 记录缓存区间；`ensure_data` 校验请求区间⊆缓存区间才复用，否则重取覆盖。
- 写入用临时文件 + `os.replace` 原子替换（零依赖，不引入 filelock）。
**验收**：先跑 2023-2024 再跑 2020-2026，第二次正确重取（不再用截断数据）；并发取同标的不损坏缓存。

### P1 — 分析页与全市场预热

#### FR-20 排名查询 API
- `GET /api/rank?strategy=&scope=&params_hash=&page=&size=&sort_by=&order=`：返回已落库 run 的排名（只含已跑过的），分页 50/页。
- `sort_by`：可选排序字段，白名单 = `symbol_name` / `total_return_pct` / `max_drawdown_pct` / `sharpe` / `win_rate_pct`；不传或非法时默认按 `total_return_pct` 降序（向后兼容）。`order`：仅接受 `asc`/`desc`，默认 `desc`；字段值为 None 的排到末尾。返回 items 含 `win_rate_pct` 字段。
- 顶部返回 `total`（已跑过数）+ `miss_count`（未跑过数）。
**验收**：跑完 10 只后查排名，返回 10 行按收益降序；分页正确；按 `win_rate_pct`/`sharpe` 等字段排序生效、None 值排末尾。

#### FR-21 分析查询页前端
- 新增 `/analysis` 页：表单（策略下拉 + 范围选择，**无日期选择器**）。
- `fetch('/api/rank')` 渲染排名表：股票名称 + 总收益率 + 最大回撤 + 夏普比 + **胜率**，按收益降序，分页。
- **列头可点击排序**：股票名称 / 总收益率 / 最大回撤 / 夏普 / 胜率 五个列头均可点击切换**升/降序**（当前排序列 ▲/▼ 高亮，切换后回到第 1 页）。
- **修复翻页第 2 页空白**：翻页逻辑加固（页码守卫、`fetch` 始终带 `sort_by/order`、空数据守卫、翻页器必渲染、`pages=Math.ceil(total/50)`）。
- 顶部显示「共 N 只已跑过，还有 M 只未跑（去数据生产页发起）」。
- 点行 → `window.open('/history?run_id=xxx')` 复用 `build_compare_from_runs` 渲染详情仪表盘。
**验收**：查排名→点行进详情，闭环可用；点列头排序生效、翻页第 2 页正常出数据。

#### FR-22 板块完成总览 API
- `GET /api/sector-status?strategy=&params_hash=`：按「策略×板块」维度聚合，返回 31 板块的完成状态（done/skipped/failed/pending 计数）。
- 纯聚合查询，不建物化表。
**验收**：跑完某板块全部成分股后，该板块显示 ✅；跑一半显示 ⏳。

#### FR-23 全市场预热
- `POST /api/batch/warmup-all`：读取 31 板块成分股去重后写入 `batch_items`（带 `sector_code`），命中预查 + 标 `skipped`，单线程池跑全部 pending。
**验收**：触发后后台逐板块跑，板块总览逐步打钩。

#### FR-24 顶部导航改造
- 所有页面顶部加导航栏：首页/快速回测（/） · 数据生产（/production） · 分析查询（/analysis） · 回测历史（/history）。
- 现有 `/` 降级为「快速回测」入口（同步单次回测，仍生成 batch_id 关联 1 个 run，但不入 batches 表）。
**验收**：四页导航切换正常；快速回测仍可用。

#### FR-25 服务重启 interrupted 处理
- 启动时扫描 `batches WHERE status='running'` → 全部 UPDATE 为 `'interrupted'`；对应 `batch_items WHERE status IN ('pending','running')` 改 `cancelled`。
- 前端展示 `interrupted` 时显示「重新发起（自动复用已完成）」按钮。
**验收**：跑到一半 kill 服务，重启后该批次标 `interrupted`，可重新发起且复用已完成部分。

### P2 — 增强与优化

#### FR-29 批次历史列表 UI

#### FR-30 排名导出 CSV

#### FR-31 数据时效提示

## 4. 非功能需求

| 类别 | 要求 |

## 7. 已知限制与偏差

- **Look-ahead 偏差**：执行价取「当日信号 + 当日收盘」，实盘需次日开盘。
- **涨跌停未建模**：极端行情当日收盘可能无法成交，回测忽略该约束。
- **费用简化**：佣金按比例单边计、未设最低 5 元；印花税仅卖方。
- **T+1 当日卖出**：清仓日若当日有 T 加仓，按清仓价强制卖出（极少出现）。
- **单标的**：不含截面/存活偏差。

### FR-33 请求反识别与防拉黑
- **目标**：从源头降低 IP 被数据源封禁的概率，保护取数链路稳定。
- 随机 User-Agent / Referer 池（8 款 UA + 6 个来源）。
- 可配置限流间隔（`STRATEGALAB_DATASOURCE_GAP`，默认 2.0s）+ 0~3s 随机抖动。
- 10% 概率完全跳过请求，进一步稀疏化节奏。
- 熔断阈值从 8 次降低为 3 次，起始冷却 60s 翻倍至 600s。

## 11. 3.0 需求（2026-07-20 新增）：拆分预热 + 增量更新数据源

> 本需求是对 v2.0 FR-23「全市场预热」的拆分与改造：将原"全市场预热"按钮耦合的两类职责——（a）从数据源取数、（b）跑回测——解耦为「更新数据源」与「回测」两个独立操作；并将"更新数据源"从「整文件覆盖、全量重拉历史区间」改为「基于已有缓存 CSV 的增量追加」。

### 产品目标

- **G1 职责解耦**：将数据获取与回测执行彻底分离，各自可独立触发、独立度量、独立失败。消除 v2.0 中"回测命中复用导致数据不刷新"（`find_existing_runs` 不比对日期区间）与"取数失败静默跳过回测"的耦合问题。
