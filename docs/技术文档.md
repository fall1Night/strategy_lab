## 1. 系统概述与设计目标

一个**自包含**的 A 股历史回测工具，分三层：

1. **入口层**：CLI（`src/strategylab/cli.py`，命令 `strategylab` / `python -m strategylab`）与 Web 服务（`src/strategylab/web.py`，命令 `strategylab-web`），二者共用同一套 engine。
2. **引擎层**（`src/strategylab/engine/`）：配置加载、指标计算、行情取数、标的搜索、单标的回测编排、仪表盘构建、策略实现、**结果落库（storage 子包）**。
3. **渲染层**（`src/strategylab/engine/vendor/`）：从数据库读取结果渲染固定版式 HTML 仪表盘（自包含，无需依赖外部路径）。

设计目标：配置驱动、零额外 Web 依赖、可复用可扩展、结果可追溯可复核。

## 4. 核心流程

### 4.1 命令行回测
1. `argparse` 解析 `--symbols/--start/--end/--strategy/--names/--out/--list-strategies/--list-runs`。
2. 策略解析：文件路径优先，否则查 `STRATEGALAB_STRATEGIES_DIR`，再查包内置 `resources/strategies/`（importlib.resources）。
3. 逐标的 `run_symbol()` → 落库并返回 `run_id` → 收集 `results`。
4. `build_compare_dashboard(results, cfg, data/index.html, start, end)`：单标的也走对比布局。

### 4.2 网页回测
- `GET /` → 表单页（标的实时搜索 JS + 策略下拉 + 日期）。
- `GET /api/search?q=` → `search_a_stocks()` 返回 JSON `{items:[{code,name,symbol}]}`。
- `POST /run` → 解析表单 → `run_backtest()`（复用 engine，结果落库）→ 注入「新建回测」浮层返回。
- `GET /history` → 历史回测页（多选列表，调 `/api/runs`）。
- `GET /api/runs?symbol=&strategy=&limit=` → `repository.list_runs()` 轻量摘要 JSON。
- `POST /compare {run_ids:[...]}` → 跨回测对比仪表盘（各 run 权益起点 rebased 到 100）。
- `GET /api/sector-stocks?code=<sw_code>` → 读取 `data/sector_stocks.json` 返回该申万一级行业的成分股列表 `{"items":[{code,name,symbol}]}`，供「按板块选股」勾选面板使用。
- **板块选股交互**：表单含「按板块选股」下拉（31 个申万一级行业）+ 成分股勾选面板（单次最多 10 只，可「全清」）；前端用 `window._stockMap` 维护「代码↔名称」映射，提交时把显示名（`real-names`）与后台代码（`real-symbols`）分离，避免中文名被误当代码造成后端 `UnicodeEncodeError` / `ValueError`。

## 5. 回测引擎设计

### 5.1 策略抽象
- `BaseStrategy`：`type` 类属性 + `run(daily, weekly, start, end, symbol, symbol_name)` → `{"equity_curve","trade_history","positions"}`。
- 自动发现：导入时 `discover_strategies()` 扫描 `engine/strategies/*.py` 收集 `BaseStrategy` 子类、以 `cls.type` 建表（`STRATEGY_REGISTRY` 由其构建）；新策略只要类文件存在且设了 `type` 即被自动注册，**无需手工登记**。

### 5.2 双入口建仓（同时间仅一笔底仓）
- **周线指标**：`wk_hist`、`wk_trigger`（路径A 触发：周 hist<0 且较上周上涨）、`wk_entry_b`（路径B：周 hist<0 & 周 J<30 & 周 J 上升）。
- **周→日对齐**：`pd.merge_asof(daily, weekly, direction="backward")`——只取「不晚于当日」的周线信号，**不使用未来数据**。
- **路径A**：周触发 armed（且 hist≥0 时 disarm）→ 日线 `J<j_buy(50)` 尾盘买入。
- **路径B**：周 `wk_entry_b` 满足 → 直接尾盘买入（不卡日线 J）。
- 单底仓约束由 `single_base_position.enabled` 控制，避免重叠建仓。

### 5.3 做T（仅日线 J 线）
- 加仓：`J` 较近 5 日高点回落 ≥ `drop_from_high`(30) 且 `J<前日J`（下降中）→ 以 `t_buy_amount` 买入（整手）。
- 停止：`J≥前日J`（反弹）不买。
- 卖出：`J>j_sell_threshold`(80) → 卖光全部加仓部分，底仓不动。

### 5.4 清仓
- 日线 MACD 水上死叉（`above_water=DIF>0 & DEA>0` 且 `DIF 下穿 DEA`）→ 当日收盘清仓底仓 + 做T。
- 优先级：清仓 > 做T > 建仓；同一根 Bar 只执行一个动作分支。

### 5.5 合并持仓明细（`_build_positions`）
按 `position_id` 分组：每组一条底仓主记录 + 若干做T 子行；`total_pnl = base_pnl + Σ做T pnl`，投资收益率基于底仓投入。

### 5.6 防御断言
- 期末强制平仓后，校验底仓区间**互不重叠**（检测到重叠即 `raise`，杜绝「未清仓又开仓」）。
- `export_results` 硬校验：长仓 only（`market=china_a` 禁止 `side=short`）、期末必须平仓、成交窗口必须落在评估区间内。

## 6. 指标与执行模型

| 项 | 口径 |
|---|---|
| MACD | `DIF=EMA12-EMA26`，`DEA=EMA(DIF,9)`，`hist=DIF-DEA`（adjust=False） |
| KDJ | `RSV=(C-L9)/(H9-L9)*100`；`K/D` 初值 50；`J=3K-2D`（向量化滚动） |
| 复权 | 前复权 `qfq` |
| 市场规则 | A 股 T+1、`lot_size=100` 整手 |
| 费用 | 佣金双边 `commission`(3bp)、印花税仅卖方 `stamp_tax`(5bp)；未设最低 5 元 |
| 执行价 | 当日信号 + 当日收盘（**含 look-ahead 偏差**，配置显式声明） |
| 期末 | `is_flat_at_end=True` 强制平仓，组合归零 |

## 7. 数据层

### 7.1 行情取数（`data_feed.py`）
- API：`http://push2his.eastmoney.com/api/qt/stock/kline/get`（本环境可达），`klt=101` 日线 / `102` 周线，`fqt=1`（前复权）。
- 代码归一：`normalize_symbol()` 接受 `600216.SH`/`sh600216`/`600216sh` 等 → `(display, secid, prefix)`；A 股 `sh→1`、`sz/bj→0`。
- 缓存：落盘到 `data/<prefix>_daily.csv` / `data/<prefix>_weekly.csv`（由 `STRATEGALAB_DATA_DIR` 控制，默认 `./data`），存在且非空则跳过取数。
- Warmup：日线早 1 年、周线早 1.5 年（保证指标不缺数据）；取数结束日取 `max(评估结束, 今天)`。

### 7.2 标的搜索（`search.py`）
- 接口：`https://datacenter-web.eastmoney.com/api/data/v1/get`（`reportName=RPT_DMSK_TS_STOCKNEW`，分页 `pageSize=500`）。
- 说明：本环境 `push2.eastmoney.com` 被出网拦截，故改用 `datacenter-web` 全量列表接口。
- 缓存：全量列表内存缓存 10 分钟（`_TTL=600`），之后本地按名称/代码 `包含` 关键词过滤。
- 代码映射：6→SH、0/3→SZ、8/4→BJ；排除 B 股（2/9 开头）。

## 8. 仪表盘渲染（`vendor`）

- `build_dashboard_data()`：接受文件路径（三件套）或预加载数据；产出 `report_data`（meta/summary/equity_curve/drawdown_curve/trade_history/modules/ui）。
- 模块类型：`overview_chart`（权益+回撤带+买卖点）、`metric_table`、`trades_table`、`position_table`（合并持仓）、`text`（策略说明/局限/免责）、`line_chart`（对比多权益曲线）。
- 对比排版（`build_compare_dashboard`）：Tab1「策略对比」含多权益曲线 + 指标对比表（总收益/年化/回撤/夏普/胜率/笔数/期末权益）+ 说明文本；各标的中独立 Tab 含各自 `position_table`。
- 持仓 / 交易明细表头固定：单标的详情仪表盘的 `position_table` / `trades_table` 表头在向下滚动时固定显示在表格顶部（CSS `position:sticky` + 不透明背景 + `z-index`，纯模板样式，不改动 JS / HTML 结构）。⚠️ 需重启服务重渲 `data/index.html` 后生效。
- 语言：`language="zh"` 锁定；模板占位符 `__REPORT_TITLE__` / `__HTML_LANG__` / `__REPORT_DATA__` 注入；渲染前校验模板无裸 `</script>`/`</style>`。

### 9.4 结果落库 Schema（已替代原「标准三件套」文件输出）

结果现写入数据库（SQLAlchemy，DB 无关），对应关系：
- `equity_points` 表：`date,value`（逐日权益，对应原 equity.csv）
- `trades` 表：`entry_date,exit_date,side,role,position_id,size,entry_price,exit_price,pnl,pnl_pct,holding_bars,symbol,symbol_name,display_symbol`（对应原 trades.csv）
- `summary` 表：`total_return_pct,annual_return_pct,max_drawdown_pct,sharpe,win_rate_pct,total_trades`（对应原 summary.json）

完整表结构及 SchemaVersion 版本表详见 [system_design.md](system_design.md)。
> 原 equity/trades/summary 三个 CSV/JSON 文件**不再产出**；如需导出可自行从数据库读取。

### 9.5 `positions`（合并持仓）结构
```json
[{
  "position_id":"...","entry_date":"...","exit_date":"...","side":"long",
  "base_size":1000,"entry_price":12.34,"exit_price":13.56,"holding_bars":20,
  "base_pnl":...,"base_pnl_pct":...,"t_count":3,
  "total_pnl":...,"total_pnl_pct":...,
  "hold_no_t_pct":...,"t_hold_to_exit_pct":...,
  "trades":[{"entry_date","exit_date","size","entry_price","exit_price","holding_bars","pnl","pnl_pct"}, ...]
}]
```
> 字段补充：`base_pnl_pct` 即「持仓不动收益率」（建仓持有到清仓、完全不做 T 的回报）；`t_hold_to_exit_pct` 即「T持有到清仓收益率」（含做 T 的全部回报，≈ `total_pnl_pct`）。两者之差 = 做 T 对这笔持仓的贡献。

## 10. 指标计算口径（`export_results` / `render_dashboard`）

- **总收益**：`final_value / window_start_value - 1`（窗口切片后重算，excludes warmup）。
- **年化收益**：`(1+total_return)^(annual_factor/periods) - 1`；`annual_factor` 由 Equity 时序频率推断（日=252，周=52）。
- **最大回撤**：`min(equity/peak - 1)` 的绝对值。
- **夏普**：`mean(日收益)/std(日收益) * sqrt(annual_factor)`。
- **胜率**：盈利笔数 / 总笔数（`pnl>0`）。
- 窗口切片：以评估 `start/end` 为准，warmup 段不计入收益/回撤。

## 14. 已知限制与偏差

- Look-ahead 偏差（当日收盘执行，实盘次日）。
- 涨跌停未建模；费用未设最低 5 元；印花税仅卖方。
- 清仓当日若含 T 加仓，按清仓价强制卖出（T+1 下极少出现）。
- 单标的，不含截面/存活偏差。
- 当前默认策略与取数以 A 股为主；`market` 字段预留港/美扩展。

## 15. v2.0 架构扩展（批量扫描 + 数据仓库化）

> v2.0 核心理念：**两页解耦（数据生产 `/production` vs 数据分析 `/analysis`）+ 一次跑多次查**。
> 回测区间固定 `2020-01-01 ~ today`；命中复用 = `strategy_name + symbol + params_hash` 一致。
> 铁律：不引入 Redis/Celery；仅用 Python 标准库（`concurrent.futures`/`threading`）+ MySQL。

### 15.1 新增数据模型

**新增表 `batches`**（批次元信息）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `batch_id` | String(36) PK | UUID4，与 `backtest_runs.batch_id` 松关联 |
| `strategy_name` / `strategy_type` | String, index | 策略标识 |
| `params_hash` | String(40), index | sha1(规范化 params_json) |
| `scope_type` | String(16) | `sector` / `pool` / `all_market` |
| `scope_value` | String(256) | 板块 code 列表 / 池 symbols / `"ALL"` |
| `total_count` / `done_count` / `failed_count` / `skipped_count` | Integer | 冗余计数 |
| `status` | String(16), index | `pending`/`running`/`done`/`failed`/`cancelled`/`interrupted` |
| `started_at` / `finished_at` / `created_at` | DateTime | |
| `error_msg` | Text | |

**新增表 `batch_items`**（批次内每只标的状态）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Integer PK auto | |
| `batch_id` | String(36) FK→`batches`, index | |
| `symbol` / `symbol_name` | String | |
| `sector_code` | String(32), nullable, index | 板块归属（池可空） |
| `status` | String(16), index | `pending`/`running`/`done`/`failed`/`skipped`/`cancelled` |
| `run_id` | String(36), nullable | 关联 `backtest_runs.run_id`（命中复用关联已有） |
| `is_reused` | Boolean | 是否命中复用 |
| `error_msg` | Text | |
| 联合唯一 | `(batch_id, symbol)` | |

**修改表 `backtest_runs`**：新增 `params_hash String(40), index, nullable`，老数据回填。

**板块状态**：纯聚合查询计算（不建物化表），按「策略×板块」维度：
```sql
SELECT sector_code, COUNT(*) total, SUM(status='done') done, SUM(status='skipped') skipped, SUM(status='failed') failed
FROM batch_items WHERE batch_id=:bid GROUP BY sector_code;
```

**Schema v1→v2 迁移**：`migrate_v1_to_v2(engine)` 幂等——`ALTER TABLE` 加 `params_hash` + 建索引 + 回填 + `CREATE TABLE batches/batch_items` + `schema_version=2`。启动时 `init_db()` 自动检测。

### 15.2 命中复用算法

提交批次时一次性预查（命中的标 `skipped` 关联已有 run，未命中的 `pending` 入队）：
```sql
SELECT r.symbol, r.run_id FROM backtest_runs r
INNER JOIN (
  SELECT symbol, MAX(created_at) AS mc FROM backtest_runs
  WHERE strategy_name=:sn AND params_hash=:ph AND symbol IN (:syms)
  GROUP BY symbol
) m ON r.symbol=m.symbol AND r.created_at=m.mc WHERE r.params_hash=:ph;
```

### 15.4 新增模块 `engine/batch_runner.py`

批量扫描后台执行器，职责：
- `submit_batch(...)`：生成 batch_id → 计算 params_hash → 命中预查 → INSERT batches/batch_items → 提交 `ThreadPoolExecutor(max_workers=8)` 后台跑 → 返回 batch_id。
- 每个任务：检查取消标志 → `UPDATE batch_items.status='running'` → 调用 `run_symbol(cfg, sym, name, '2020-01-01', today, out_dir, batch_id)` → 成功 `done`+`run_id` / 失败 `failed`+`error_msg` → 原子 `UPDATE batches SET done_count=done_count+1`。
- `_CANCEL_FLAGS: dict[batch_id, threading.Event]` 内存取消标志。
- 单只失败 `try/except` 不终止整批。
- 服务重启：启动时 `batches WHERE status='running'` → `interrupted`；`batch_items WHERE status IN ('pending','running')` → `cancelled`。

### 15.5 缓存修复（`data_feed.py`，修历史 bug）

- 新增 `<prefix>_meta.json` 记录缓存区间：`{"daily":{"first","last","rows"}, "weekly":{...}, "version":1}`。
- `ensure_data` 校验：请求区间 ⊆ 缓存区间 → 复用；⊆ 不成立 → 重取覆盖；meta 缺失 → 视为无缓存。
- 写入用临时文件 + `os.replace` 原子替换（零依赖，不引入 filelock）。
- 老 缓存迁移：`python -m strategylab.migrate_cache`（P2）补建 meta.json。

### 15.6 并发与性能

| 维度 | 方案 |
|------|------|
| ThreadPoolExecutor | `max_workers=8`（`STRATEGALAB_BATCH_WORKERS` 可配） |
| MySQL 连接池 | `pool_size=10, max_overflow=5, pool_pre_ping=True, pool_recycle=1800` |
| 计数并发安全 | 原子 SQL `UPDATE batches SET done_count=done_count+1 WHERE batch_id=?` |
| bulk_insert_mappings | `save_run` 改批量写，比逐条 append 快 10-50 倍 |
| 行情缓存并发安全 | `tempfile + os.replace` 原子写；进程内 `_SYMBOL_LOCKS`（P2）防同 symbol 并发取数 |
| 排名查询 | `(strategy_name, params_hash)` 复合索引 + 分页 50/页 |

### 15.7 前端两页

- **数据生产页 `/production`**：表单（策略+范围，无日期）+ 进度区（2s 轮询）+ 板块总览区（31 板块 ✅/⏳/未跑）+ 历史批次折叠区 + 取消按钮。
- **分析查询页 `/analysis`**：表单（策略+范围，无日期）+ 排名表（股票名+总收益+回撤+夏普+**胜率**，降序分页）+ 点行进详情；**五个列头（股票名称/总收益率/最大回撤/夏普/胜率）可点击排序**（当前排序列 ▲/▼ 金色高亮，切换后回到第 1 页），已修复翻页第 2 页空白。
- **顶部导航**：首页/快速回测（/）· 数据生产（/production）· 分析查询（/analysis）· 回测历史（/history）。`/` 降级为快速回测。

## 16. 多数据源扩展（2026-07-19 新增）

### 16.1 架构模式
采用「抽象基类（模板方法）+ 适配器 + 工厂 + 容灾策略」四位一体：
- **模板方法**：`DataSource` 基类实现 `fetch_kline` 骨架（限流→熔断→重试→复位），子类只实现 `_raw_fetch_kline`。
- **适配器**：`EastmoneyDataSource` / `AkshareDataSource`(新浪) / `TushareDataSource` / `BrokerDataSource`(P2桩)。
- **工厂**：`DataSourceFactory` 按配置构建源、解析"全局默认源/按品种覆盖/备用源顺序"。
- **容灾**：`KlineProvider` 选源→查缓存→失败按链切换→记切换事件。

### 16.2 子包结构
`src/strategylab/engine/datasource/` 共 13 个文件：

| 文件 | 职责 |
|------|------|
| `__init__.py` | 对外导出公共 API |
| `exceptions.py` | 异常层级：DataSourceError / MissingDependencyError 等 |
| `base.py` | DataSource 抽象基类 + SymbolSpec + 随机头池 `random_headers()` + `random_sleep()` |
| `config.py` | DataSourceConfig 数据类 + `from_env()` 解析 `STRATEGALAB_*` |
| `eastmoney.py` | 东财 push2his 适配器（100% 保留既有行为） |
| `factory.py` | DataSourceFactory 工厂 |
| `cache.py` | KlineCache 磁盘缓存（source 感知路径 + 旧格式兼容） |
| `switch_log.py` | SwitchEvent / SwitchLog 切换日志 |
| `provider.py` | KlineProvider.ensure_data 编排（选源→查缓存→容灾链→写缓存） |
| `akshare_src.py` | 新浪源适配器 `stock_zh_a_daily`（日线 + 周线聚合） |

## 17. 请求反识别与防拉黑（2026-07-19 新增）

### 17.1 随机请求头
`base.py` 中的 `random_headers()` 函数维护 8 款浏览器 UA + 6 个 Referer 来源池，每次请求随机组合，防止固定指纹被识别为爬虫。

### 17.2 限流与抖动
- 每源独立限流（实例级 `_FETCH_LOCK`），默认间隔 2.0s（可配）。
- `_throttle()` 在基础间隔上增加 0~3s 随机抖动。
- 10% 概率完全跳过本次请求，让请求节奏进一步稀疏化。

### 17.3 熔断与冷却
- 连续 3 次失败（原 8）触发熔断，起始冷却 60s，翻倍至上限 600s。
- 每源独立（东财被限不误伤 akshare）。

### 17.4 数据源切换
因东财 IP 被封，`VER=2026-07-19` 起默认数据源改为 `akshare`（新浪接口 `stock_zh_a_daily`）。akshare 适配器已将底层从东财 `stock_zh_a_hist` 换为新浪 `stock_zh_a_daily`，周线由日线 `resample("W-FRI")` 聚合生成。

## 18. 启动与服务增强（2026-07-19 新增）
- `src/strategylab/__main__.py`：`python -m strategylab` 等价于 `python -m strategylab.web`。
- `restart.bat` / `restart.sh`：一键杀 8000 端口旧进程 + 重启。
- `ThreadingHTTPServer.allow_reuse_address = True`：解决 TIME_WAIT 端口复用失败。
