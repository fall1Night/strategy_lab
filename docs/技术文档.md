## 1. 系统概述与设计目标

一个**自包含**的 A 股历史回测工具，分三层：

1. **入口层**：CLI（`src/strategylab/cli.py`，命令 `strategylab` / `python -m strategylab`）与 Web 服务（`src/strategylab/web.py`，命令 `strategylab-web`），二者共用同一套 engine。
2. **引擎层**（`src/strategylab/engine/`）：配置加载、指标计算、行情取数、标的搜索、单标的回测编排、仪表盘构建、策略实现、**结果落库（storage 子包）**。
3. **渲染层**（`src/strategylab/engine/vendor/`）：从数据库读取结果渲染固定版式 HTML 仪表盘（自包含，无需依赖外部路径）。

设计目标：配置驱动、零额外 Web 依赖、可复用可扩展、结果可追溯可复核。

## 4. 核心流程

### 4.1 命令行回测
1. `argparse` 解析 `--symbols/--start/--end/--strategy/--names/--out/--list-strategies/--list-runs`。
2. 策略解析：文件路径优先，否则查 `STRATEGALAB_STRATEGIES_DIR`，再查包内置 `resources/strategies/`（importlib.resources）。
3. 逐标的 `run_symbol()` → 落库并返回 `run_id` → 收集 `results`。
4. `build_compare_dashboard(results, cfg, data/index.html, start, end)`：单标的也走对比布局。

### 4.2 网页回测
- `GET /` → 表单页（标的实时搜索 JS + 策略下拉 + 日期）。
- `GET /api/search?q=` → `search_a_stocks()` 返回 JSON `{items:[{code,name,symbol}]}`。
- `POST /run` → 解析表单 → `run_backtest()`（复用 engine，结果落库）→ 注入「新建回测」浮层返回。
- `GET /history` → 历史回测页（多选列表，调 `/api/runs`）。
- `GET /api/runs?symbol=&strategy=&limit=` → `repository.list_runs()` 轻量摘要 JSON。
- `POST /compare {run_ids:[...]}` → 跨回测对比仪表盘（各 run 权益起点 rebased 到 100）。
- `GET /api/sector-stocks?code=<sw_code>` → 读取 `data/sector_stocks.json` 返回该申万一级行业的成分股列表 `{"items":[{code,name,symbol}]}`，供「按板块选股」勾选面板使用。
- **板块选股交互**：表单含「按板块选股」下拉（31 个申万一级行业）+ 成分股勾选面板（单次最多 10 只，可「全清」）；前端用 `window._stockMap` 维护「代码↔名称」映射，提交时把显示名（`real-names`）与后台代码（`real-symbols`）分离，避免中文名被误当代码造成后端 `UnicodeEncodeError` / `ValueError`。

## 5. 回测引擎设计

### 5.1 策略抽象
- `BaseStrategy`：`type` 类属性 + `run(daily, weekly, start, end, symbol, symbol_name)` → `{"equity_curve","trade_history","positions"}`。
- 注册表：`STRATEGY_REGISTRY = {type: 类}`，新策略继承基类并登记即可。

### 5.2 双入口建仓（同时间仅一笔底仓）
- **周线指标**：`wk_hist`、`wk_trigger`（路径A 触发：周 hist<0 且较上周上涨）、`wk_entry_b`（路径B：周 hist<0 & 周 J<30 & 周 J 上升）。
- **周→日对齐**：`pd.merge_asof(daily, weekly, direction="backward")`——只取「不晚于当日」的周线信号，**不使用未来数据**。
- **路径A**：周触发 armed（且 hist≥0 时 disarm）→ 日线 `J<j_buy(50)` 尾盘买入。
- **路径B**：周 `wk_entry_b` 满足 → 直接尾盘买入（不卡日线 J）。
- 单底仓约束由 `single_base_position.enabled` 控制，避免重叠建仓。

### 5.3 做T（仅日线 J 线）
- 加仓：`J` 较近 5 日高点回落 ≥ `drop_from_high`(30) 且 `J<前日J`（下降中）→ 以 `t_buy_amount` 买入（整手）。
- 停止：`J≥前日J`（反弹）不买。
- 卖出：`J>j_sell_threshold`(80) → 卖光全部加仓部分，底仓不动。

### 5.4 清仓
- 日线 MACD 水上死叉（`above_water=DIF>0 & DEA>0` 且 `DIF 下穿 DEA`）→ 当日收盘清仓底仓 + 做T。
- 优先级：清仓 > 做T > 建仓；同一根 Bar 只执行一个动作分支。

### 5.5 合并持仓明细（`_build_positions`）
按 `position_id` 分组：每组一条底仓主记录 + 若干做T 子行；`total_pnl = base_pnl + Σ做T pnl`，投资收益率基于底仓投入。

### 5.6 防御断言
- 期末强制平仓后，校验底仓区间**互不重叠**（检测到重叠即 `raise`，杜绝「未清仓又开仓」）。
- `export_results` 硬校验：长仓 only（`market=china_a` 禁止 `side=short`）、期末必须平仓、成交窗口必须落在评估区间内。

## 6. 指标与执行模型

| 项 | 口径 |
|---|---|
| MACD | `DIF=EMA12-EMA26`，`DEA=EMA(DIF,9)`，`hist=DIF-DEA`（adjust=False） |
| KDJ | `RSV=(C-L9)/(H9-L9)*100`；`K/D` 初值 50；`J=3K-2D`（向量化滚动） |
| 复权 | 前复权 `qfq` |
| 市场规则 | A 股 T+1、`lot_size=100` 整手 |
| 费用 | 佣金双边 `commission`(3bp)、印花税仅卖方 `stamp_tax`(5bp)；未设最低 5 元 |
| 执行价 | 当日信号 + 当日收盘（**含 look-ahead 偏差**，配置显式声明） |
| 期末 | `is_flat_at_end=True` 强制平仓，组合归零 |

## 7. 数据层

### 7.1 行情取数（`data_feed.py`）
- API：`http://push2his.eastmoney.com/api/qt/stock/kline/get`（本环境可达），`klt=101` 日线 / `102` 周线，`fqt=1`（前复权）。
- 代码归一：`normalize_symbol()` 接受 `600216.SH`/`sh600216`/`600216sh` 等 → `(display, secid, prefix)`；A 股 `sh→1`、`sz/bj→0`。
- 缓存：落盘到 `data/<prefix>_daily.csv` / `data/<prefix>_weekly.csv`（由 `STRATEGALAB_DATA_DIR` 控制，默认 `./data`），存在且非空则跳过取数。
- Warmup：日线早 1 年、周线早 1.5 年（保证指标不缺数据）；取数结束日取 `max(评估结束, 今天)`。

### 7.2 标的搜索（`search.py`）
- 接口：`https://datacenter-web.eastmoney.com/api/data/v1/get`（`reportName=RPT_DMSK_TS_STOCKNEW`，分页 `pageSize=500`）。
- 说明：本环境 `push2.eastmoney.com` 被出网拦截，故改用 `datacenter-web` 全量列表接口。
- 缓存：全量列表内存缓存 10 分钟（`_TTL=600`），之后本地按名称/代码 `包含` 关键词过滤。
- 代码映射：6→SH、0/3→SZ、8/4→BJ；排除 B 股（2/9 开头）。

## 8. 仪表盘渲染（`vendor`）

- `build_dashboard_data()`：接受文件路径（三件套）或预加载数据；产出 `report_data`（meta/summary/equity_curve/drawdown_curve/trade_history/modules/ui）。
- 模块类型：`overview_chart`（权益+回撤带+买卖点）、`metric_table`、`trades_table`、`position_table`（合并持仓）、`text`（策略说明/局限/免责）、`line_chart`（对比多权益曲线）。
- 对比排版（`build_compare_dashboard`）：Tab1「策略对比」含多权益曲线 + 指标对比表（总收益/年化/回撤/夏普/胜率/笔数/期末权益）+ 说明文本；各标的中独立 Tab 含各自 `position_table`。
- 语言：`language="zh"` 锁定；模板占位符 `__REPORT_TITLE__` / `__HTML_LANG__` / `__REPORT_DATA__` 注入；渲染前校验模板无裸 `</script>`/`</style>`。

### 9.4 结果落库 Schema（已替代原「标准三件套」文件输出）

结果现写入数据库（SQLAlchemy，DB 无关），对应关系：
- `equity_points` 表：`date,value`（逐日权益，对应原 equity.csv）
- `trades` 表：`entry_date,exit_date,side,role,position_id,size,entry_price,exit_price,pnl,pnl_pct,holding_bars,symbol,symbol_name,display_symbol`（对应原 trades.csv）
- `summary` 表：`total_return_pct,annual_return_pct,max_drawdown_pct,sharpe,win_rate_pct,total_trades`（对应原 summary.json）

完整表结构及 SchemaVersion 版本表详见 [system_design.md](system_design.md)。
> 原 equity/trades/summary 三个 CSV/JSON 文件**不再产出**；如需导出可自行从数据库读取。

### 9.5 `positions`（合并持仓）结构
```json
[{
  "position_id":"...","entry_date":"...","exit_date":"...","side":"long",
  "base_size":1000,"entry_price":12.34,"exit_price":13.56,"holding_bars":20,
  "base_pnl":...,"base_pnl_pct":...,"t_count":3,
  "total_pnl":...,"total_pnl_pct":...,
  "hold_no_t_pct":...,"t_hold_to_exit_pct":...,
  "trades":[{"entry_date","exit_date","size","entry_price","exit_price","holding_bars","pnl","pnl_pct"}, ...]
}]
```
> 字段补充：`base_pnl_pct` 即「持仓不动收益率」（建仓持有到清仓、完全不做 T 的回报）；`t_hold_to_exit_pct` 即「T持有到清仓收益率」（含做 T 的全部回报，≈ `total_pnl_pct`）。两者之差 = 做 T 对这笔持仓的贡献。

## 10. 指标计算口径（`export_results` / `render_dashboard`）

- **总收益**：`final_value / window_start_value - 1`（窗口切片后重算，excludes warmup）。
- **年化收益**：`(1+total_return)^(annual_factor/periods) - 1`；`annual_factor` 由 Equity 时序频率推断（日=252，周=52）。
- **最大回撤**：`min(equity/peak - 1)` 的绝对值。
- **夏普**：`mean(日收益)/std(日收益) * sqrt(annual_factor)`。
- **胜率**：盈利笔数 / 总笔数（`pnl>0`）。
- 窗口切片：以评估 `start/end` 为准，warmup 段不计入收益/回撤。

## 11. 部署与运维

- **依赖**：`pip install -e .`（含 sqlalchemy/pymysql/pandas/numpy/python-dotenv）；Web/渲染零额外依赖。
- **启动**：`strategylab-web`（或 `PORT=9000 strategylab-web`）；命令行 `strategylab --symbols ... --start ... --end ...`。
- **停止**：`Ctrl+C`；残留进程用 `netstat` 找 PID 后 `taskkill /PID <pid> /F`。
- **缓存清理**：删除 `data/<prefix>_{daily,weekly}.csv` 可强制重取行情；搜索缓存 10 分钟自动过期。

## 14. 已知限制与偏差

- Look-ahead 偏差（当日收盘执行，实盘次日）。
- 涨跌停未建模；费用未设最低 5 元；印花税仅卖方。
- 清仓当日若含 T 加仓，按清仓价强制卖出（T+1 下极少出现）。
- 单标的，不含截面/存活偏差。
- 当前默认策略与取数以 A 股为主；`market` 字段预留港/美扩展。
